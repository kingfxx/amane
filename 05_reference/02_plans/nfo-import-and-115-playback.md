# NFO 导入与 115 播放开发计划

日期: 2026-11-06. 状态: 代码与本地验证完成, 115 真实 Chrome 登录态搜索和 Master 接管待验收.

## 已确认的方向

- 两项功能独立开发、安装、更新和停用, 相互不依赖.
- NFO 导入采用 Amane 插件; 主机只补充通用导入能力, NFO 格式规则留在插件中.
- 115 播放采用独立篡改猴脚本; 在 Amane 影片详情页按番号搜索, 点击后打开 115master 页面.
- 115 搜索使用当前 Chrome 中可用的 115 登录状态, 不要求向 Amane 提交 Cookie.
- 元数据导入不以正片存在为前提; CloudDrive 挂载仅影响本地文件访问.
- 实施前先确定代码分支与插件目录, 不修改远程仓库.

## 当前工作区

功能分支为 `codex/nfo-import-and-115-playback`. 此前未完成的外部播放链接改动已移除; 浏览器脚本不依赖主机播放接口改动. 开发依赖已补全, 仅执行本地开发与验证, 未修改远程仓库或实际媒体目录.

两个安装包位于 `dist/extensions/`, 安装说明见 [extensions/README.md](../../extensions/README.md). 用户示范目录已通过只读解析, 识别到三张图片、一个正片、一个远程链接和一个本地预览片路径; 原始 NFO 的裸 `&` 在内存中修复并提示. 隔离数据库已通过插件安装、页面预览、导入提交及任务完成验证.

## 方案一: 115 浏览器播放脚本

### 交互流程

1. 用户在已安装篡改猴和 115master 的 Chrome 中打开 Amane 影片详情页.
2. 配套脚本识别当前影片番号, 在详情操作区显示查询状态.
3. 脚本通过 `GM_xmlhttpRequest` 查询 115 文件, 使用脚本管理器允许发送的当前浏览器登录凭据.
4. 单个匹配显示「115 播放」; 多个匹配提供文件名、大小与选择入口.
5. 用户点击候选后, 通过 `GM_openInTab` 打开 `https://115.com/web/lixian/master/video/?pick_code=...`, 由已安装的 115master 接管播放.

查询期间不打开 115 页面; 播放页面仅在用户点击时打开. 不要求先导入 NFO 或关联本地媒体文件.

### 实现边界

- 优先使用现有页面信息或公开详情 API 取得番号, 不引入 Amane 专用播放 API、后端 Cookie 或码流代理.
- 页面注入与 115 查询分离; DOM 定位集中在适配模块, 不依赖构建生成的 CSS 类名.
- 支持 React 页面局部导航、前进后退及直接打开详情页; 同一影片只保留一份控件.
- 默认不修改主项目. 如现有页面没有可靠挂载位置, 先提出最小通用页面标记方案, 再调整计划.
- 脚本只匹配用户配置的 Amane 地址, 跨域权限只声明所需的 115 域名.
- 不读取、导出或持久化 Cookie, 不将搜索结果或登录凭据发送到 Amane 服务端或其它服务.
- 搜索结果按番号边界、视频扩展名过滤, 排除相似番号和预览片; 同一文件按 `pick_code` 去重.
- 对搜索接口的分页或截断进行显式处理, 不把不完整结果显示为全部结果.
- 查询并发受限, 同号请求合并, 短期缓存匹配结果; 支持手动重新查询与清除缓存.
- 切换影片后取消或忽略旧请求; 旧结果不能写入新影片页面.
- 未匹配、登录失效、接口限制、超时与其它请求失败分别处理; 无法确定的错误不推断为未登录.

### 首阶段验证

在用户实际 Chrome、篡改猴和 115 登录环境中验证带凭据的跨域搜索. 附件表明原脚本采用该机制, 但浏览器 Cookie 策略和脚本管理器权限仍需实际验证. 未通过前, 不假定 Python 插件或普通网页请求可以替代.

### 验收标准

- 已登录 115 且匹配成功时, 不打开 115 页面即可显示播放入口.
- 单匹配、多匹配、无匹配均有明确状态; 相似番号不会产生误匹配.
- 点击后打开携带正确 `pick_code` 的 Master 页面, 能由用户已安装的脚本接管.
- 登录失效和网络故障不显示为「未找到文件」.
- 页面切换与缓存刷新不会保留其它影片的链接.
- 停用脚本后 Amane 恢复原有页面行为; 不依赖主机外部播放接口改动.

## 方案二: NFO 导入插件

### 主机与插件职责

| 组件 | 职责 |
| --- | --- |
| Amane 主机 | 通用导入入口、路径校验、预览与冲突处理、任务执行、资源存储、数据库写入 |
| NFO 导入插件 | 目录识别、NFO 解析、字段映射、附属文件与正片匹配 |

现有插件接口只开放影片来源与播放源. 需要增补通用导入契约, 不能通过导入 Amane 私有数据库模块实现插件业务. 主机负责固定的导入界面, 首版不开放插件自定义 React 页面或任意 API 路由.

### 导入流程

1. 安装并启用 NFO 导入插件, 从统一导入入口选择服务器目录与是否递归.
2. 主机校验目录授权范围; 插件生成候选, 展示番号、元数据、关联文件、已有影片冲突与异常.
3. 用户选择候选并执行导入. 预览阶段不复制资源、不写入元数据、不提交刮削任务.
4. 主机再次校验源文件与冲突状态, 通过任务系统逐影片执行, 展示进度、成功、跳过与失败原因.
5. 成功影片进入片库. 正片仅在明确指定所属媒体库且路径归属成立时登记和关联.

### 解析与匹配规则

- 首版支持电影类 XML NFO; 正确处理编码声明、BOM、CDATA、缺失字段及重复字段.
- 番号优先读取 NFO 的明确标识; 其次按文件名或标题识别. 候选互相冲突或无法确定时要求处理, 不猜测写入.
- 标题移除与已确认番号重复的前缀; 演员、导演和标签按现有模型保存, `tag` 与 `genre` 去重.
- 海报、横版封面和剧照优先使用已匹配的本地文件; 缺失时保留受支持的远程地址, 导入过程不主动联网下载.
- 预告片默认保存并使用 NFO 中受支持的远程链接; 同时独立保存匹配到的本地预览片路径, 不以本地路径覆盖远程链接. 未提供远程链接时保留空值, 不自动切换本地播放.
- `poster` 映射海报, `thumb` 映射横版封面, `fanart` 作为备用横版封面, `extrafanart` 映射剧照; 预览界面显示实际映射.
- 支持同名附属文件与 `trailers`、`extrafanart` 子目录. 通用名称仅在所属影片明确时使用, 同目录多影片不共享猜测结果.
- 正片匹配不包含预览片, 支持同一番号关联多个分段文件; 无正片的 NFO 同样可以导入.
- 字幕文件首版只参与现有字幕关联判断, 不新增字幕转换或播放器功能.

### 写入与兼容边界

- 默认补充已有影片的空字段; 显式勾选覆盖后只用非空导入值替换未锁定字段. 字段锁、用户标签和评论始终保留, 缺失字段不清空已有值.
- 重复导入保持幂等; 番号大小写、同号多个目录和并发刮削的判定与写入遵循现有数据库事务约束.
- 导入记录保留独立来源与资源引用, 不伪装成内置刮削来源; 不改写现有来源路由和字段优先级.
- 本地图片复制至受管理的资源存储; 本地预览片默认只保存服务器路径及影片关联, 不复制、不读取视频内容. 正片只登记路径, 不复制或计算内容指纹.
- 本地预览片路径与远程预告片链接分别持久化到 SQLite; 路径移动或挂载不可用不影响远程链接. 首版路径用于保留关联信息, 本地播放及显式复制选项不属于当前范围.
- 资源复制仅在用户执行导入后发生, 不修改、重命名、移动或删除源目录中的任何文件.
- 目录遍历、文件检查及复制进入线程池; CloudDrive 挂载延迟不能阻塞事件循环.
- 校验真实路径与符号链接归属, 限制 XML 和资源大小, 禁用外部实体解析; NFO 引用不能扩大授权读取范围.
- 导入不触发网络刮削、演员刮削或自动整理; 不改变原有扫描与刮削的默认行为.
- 单影片失败不阻断其它影片; 重试与取消以影片为单位, 不残留半完成的影片写入. 未引用资源沿用现有回收机制.
- 插件卸载只移除执行能力, 已导入元数据和资源保持可用.
- 明确最低宿主版本与导入契约版本; 已有影片来源与播放插件继续兼容. 版本声明方式在接口设计阶段确定.

### 验收标准

- 用户已提供的示范目录可以离线导入 NFO、复制三张图片、保存远程预告片链接及本地预览片路径, 并正确关联正片.
- 预览片默认播放地址保留 NFO 远程链接, 导入后资源目录中无本地预览片副本; 没有远程链接或本地路径失效时不自动更换播放来源.
- 截图通过剧照目录或明确引用导入, 无正片的目录也能进入片库.
- 重复导入、已有字段、锁定空字段、同号多个正片均符合写入规则.
- XML 损坏、非法数值、编号冲突、缺失资源、越界引用与挂载不可用均有明确结果.
- 安装、启用、停用、更新和卸载可以独立操作; 停用后原有流程与测试保持通过.

## 上游更新与维护

- 主项目通用接口、NFO 插件、115 浏览器脚本分别维护版本和逻辑提交; 插件业务代码最终独立于主项目仓库分发.
- 开发初期可以在独立扩展目录组织代码, 不因尚未创建独立仓库阻塞本地验证; 不自动创建或发布远程仓库.
- 原项目作为 `upstream`, 自有仓库作为 `origin`; 跟踪分支保持上游状态, 定制分支合并上游更新.
- 上游更新后检查插件安装与导入契约、资源读取和详情页面适配; 115 接口或 Master 页面变化由浏览器脚本独立更新.
- 通用接口提交与插件提交分离, 减少合并冲突. 上游贡献、push、发布或 PR 操作均需用户明确授权.
- 开发检查优先使用根 `Justfile` 入口; 修改 API 后重新生成客户端. 只在实施阶段更新对应开发索引, 计划不写入 `docs/dev/` 作为当前能力.
